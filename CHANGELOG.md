# Changelog Policy

ZEQAT follows these principles when maintaining the changelog:

### Accuracy

Changes should reflect actual development work.

### Transparency

Security-related changes should be documented where disclosure does not create additional security risk.

### No False Claims

A feature should not be described as independently audited, penetration-tested, or externally verified unless the corresponding evidence exists.

### Security-Sensitive Changes

Some security changes may be intentionally described at a high level when publishing technical details could make exploitation easier.

### Versioning

Future releases may use version numbers such as:

```text
v1.0.0
v1.1.0
v1.1.1
```

The exact versioning strategy may evolve as ZEQAT development progresses.

# Status Terminology

ZEQAT uses the following terminology:

- **Added** — a new feature or component was introduced.
- **Changed** — an existing feature or component was modified.
- **Fixed** — a bug or security issue was corrected.
- **Security** — a security-related improvement or change.
- **Deprecated** — a feature is being phased out.
- **Removed** — a feature or component was removed.
- **Planned** — intended future development.
- **Verified** — supported by documented independent or external verification.
